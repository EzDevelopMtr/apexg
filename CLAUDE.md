# APEX GYM — engineering conventions

Gym management system. Source of truth for requirements is the SRS
("ERS GK", Spanish). Requirement IDs (`RF-xx`, `RNF-xx`) are cited in code
comments where a rule is non-obvious.

## Language

- **Code is English.** Types, fields, functions, props, handlers, files.
- **The SRS is Spanish.** Translate through [docs/GLOSSARY.md](docs/GLOSSARY.md),
  never ad hoc. Add missing terms to the glossary before using them.
- **User-facing copy is Spanish.** Every string the receptionist or admin reads
  stays in Spanish. Keep it out of logic — it belongs in the component that
  renders it.

## Architecture — dependencies flow one way

```
core  ←  data  ←  module-*  ←  web
```

`core` never imports upward. A membership expiry calculation must run in a
plain Node test with no React, no Next and no database.

| Package    | Contains                                 | Must not contain              |
| ---------- | ---------------------------------------- | ----------------------------- |
| `core`     | Domain types, business rules, pure funcs | React, fetch, Next, JSX       |
| `ui`       | Presentational primitives                | Business rules, Next, routing |
| `module-*` | One business module: hooks + components  | Rules that belong in `core`   |
| `web`      | Routes, session, layout                  | Business logic                |

## Rules

1. **Business rules live in `core`, never in a component.** Prices, terms,
   minimum installments and state transitions come from `core`. A hardcoded
   `<option value="Monthly">` is a bug.
2. **Money is integers (cents).** Never floats. `0.1 + 0.2 !== 0.3` and this
   system computes balances and accumulated profit (RNF-07).
3. **Open/closed via data, not conditionals.** Adding a client section or a
   membership type means adding a record, not editing a component. Sections
   carry their own predicate.
4. **Components are dumb.** State and orchestration live in hooks. If a
   component both fetches/filters and renders, split it.
5. **Depend on abstractions.** Components receive data through a hook or props,
   never by importing a concrete data source.
6. **Type the narrow thing.** Prefer literal unions over `string`. Validators
   that narrow must be type guards (`value is SectionId`).
7. **IDs are generated by the data layer**, never in a component.

## Colour

Every colour resolves through the tokens in `packages/ui/src/theme.css`.
A raw palette class — `bg-slate-100`, `text-blue-600` — is a bug: it puts a
decision outside the one file that owns them.

Two families, kept apart on purpose:

- **Brand** (`shell`, `brand`, `canvas`, `body`) carries identity, and lives in
  the cool half of the wheel.
- **Status** (`ok`, `warn`, `danger`, `idle`) carries meaning — the client
  states of SRS §4.2. Green, amber and red belong to them alone. An accent that
  drifted into those hues would stop "Activo" reading as a signal.

Grounds: `.ground-grain` everywhere, `.ground-grid` only on the module
selector — the one screen with no table for it to compete with.

## Comments

JSDoc on the public exports of `core` — they are the shared contract.
Inline comments only for non-obvious business rules, citing the requirement:

```ts
// RF-19: validated here rather than in the form because the API must
// reject it too (RNF-07: financial calculations are traceable).
```

Do not narrate what the code already says.

## Guardrails

`pnpm verify` runs lint + typecheck + tests. CI runs it on every PR.

- oxlint caps files at 200 lines and functions at 80 (tests exempt).
- TypeScript runs `strict` + `noUncheckedIndexedAccess`.
- Every rule in SRS §4 must have a test in `core`. No exceptions — RNF-07.

## Commands

```bash
pnpm dev        # http://localhost:3000
pnpm verify     # lint + typecheck + test
pnpm test       # vitest
pnpm format     # prettier
```
